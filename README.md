# jav-trans

jav-trans 是一个面向 Windows 和 NVIDIA 显卡的本地字幕生成工具。选择视频后，它会自动完成日语语音识别、字幕时间轴、可选翻译和质量检查，输出日文、译文或中日双语 SRT。

视频、音频、语音识别和时间轴始终在本机处理。只有选择 API 翻译时，字幕文本才会发送到你配置的服务；仅日文和本地翻译模式不会上传媒体或字幕。

![网页控制台主界面](docs/images/ui-web-console.png)

## 主要功能

- 本地网页控制台：选择视频、调整设置、查看进度并打开结果。
- 日语识别与精细时间轴：使用 Qwen3-ASR 1.7B 和 CTC 对齐生成字幕。
- 翻译前按日语原文断句：完整句优先；确实过长时，只在完整分句和实测停顿处拆分。译文沿用原单元的时间轴，不再按字数拆成多条字幕。
- 非语义人声过滤：整条只有喘息、呻吟等非语义发声的字幕会被删除，一条里只有一段是的会被切掉那一段；含可辨识词语的内容保留。
- 三种输出：仅日文、仅译文、中日双语。中日两轨各以对应的 Netflix 字幕规范为排版目标，每条最多两行；日文按规范不使用句号和顿号，改用空格分隔。
- 两种翻译方式：OpenAI 兼容 API，或本地 Hy-MT2-7B Q4。
- 质量报告：标出时间轴、字幕布局和翻译中的可疑项，方便按时间码复查。
- 断点与缓存：失败后可以复用已有识别结果，不必总是从头开始。

## 运行要求

- Windows 10/11。
- NVIDIA 独立显卡；8GB 及以上显存推荐，当前 ASR 模型要求至少 6144MiB 物理显存。
- Windows 发布包已包含 FFmpeg Shared，无需另行下载或安装。首次启动需要联网安装 Python 依赖；ASR 模型约 3.9GB，本地翻译模型约 4.6GB。
- 将发布包解压到普通可写目录，并预留至少 15GB 空间。

正式 ASR 不会静默回退到 CPU。CUDA 不可用、驱动过旧或显存不足时，任务会明确报错。

## 快速开始

1. 从 [Releases](https://github.com/jaykwok/jav-trans/releases) 下载并解压 Windows 发布包。
2. 双击 `jav-trans.exe`。首次启动会自动安装依赖；中断后重新运行即可继续。
3. 在网页控制台中选择一个或多个视频。
4. 选择字幕模式和翻译方式，按需填写 API Key 或本地模型设置。
5. 点击“开始任务”，完成后从任务卡打开 SRT 和可选的质量报告。

发布包自带 FFmpeg Shared。普通用户无需单独配置 FFmpeg；只有从源码运行时才需要自行安装。

首次使用建议勾选“不翻译（仅日文字幕）”跑一个短视频，以确认 CUDA、模型下载和输出目录都正常。

## 选择处理模式

| 模式 | 是否发送字幕文本 | 适合场景 |
| --- | --- | --- |
| 仅日文 | 否 | 最快验证环境，或只需要日文 SRT |
| 本地翻译 | 否 | 隐私优先、零 API 成本的中文草稿 |
| API 翻译 | 是 | 需要全片参考、角色参考和可选的语义复核 |

API 模式默认使用 OpenRouter。通常只需填写 API Key；如果改用其他服务，Base URL 与模型名必须配套：OpenRouter 使用 `厂商/模型` 形式，DeepSeek 官方 API 使用裸模型名。此外该服务必须提供 Responses 接口（`/responses`）——程序只使用这一个协议面，只支持 Chat Completions 的旧接口和中转用不了。

本地翻译固定使用 `Hy-MT2-7B-Q4_K_M.gguf`，首次使用时自动下载。先安装 llama.cpp：

```powershell
winget install -e --id ggml.llamacpp
```

然后在网页控制台选择“本地 Hy-MT2”。本地后端逐条翻译已经确定的日语原文单元，结合附近原文和当前句命中的用户术语；角色参考与全片参考仅用于 API 翻译。本地模型仍可能误判省略的人物或动作，建议复查。

翻译以保留否定、条件、数量、施受关系和原句语气为先，不为凑字数省略含义。同一句日语在不同语境中可以有不同译法，正常短译文不会仅因长短比例异常而被扩写。原文缺少可靠断句点时会保留较长字幕，质量报告会标出超长；中文只做同一条字幕内的换行排版。

API 翻译可额外开启语义复核：在 `.env` 设置 `TRANSLATION_SEMANTIC_REVIEW_ENABLED=1` 后重启。默认关闭，开启会增加 API 用量和等待时间；每次最多检查 80 条候选（可用 `TRANSLATION_SEMANTIC_REVIEW_MAX_IDS` 调整），修改须经过原文证据检查和第二次独立比较。复核记录保留修改前后文本；它仍是模型判断，不能代替人工检查。

任务运行期间切换翻译后端或本地 server 路径，会让正在运行的任务报错停止并说明原因——它已经在用的那个实例被这次切换关掉了，中途改用新实例会让同一部片子前后半段来自不同模型。改完设置重新运行该任务即可。

NVIDIA 用户可从 [llama.cpp 官方 Releases](https://github.com/ggml-org/llama.cpp/releases) 下载 CUDA 版。先运行 `nvidia-smi` 查看驱动支持的 CUDA 版本，再选择不高于该版本的 Windows x64 压缩包：

- CUDA 12：`llama-b<版本号>-bin-win-cuda-12.x-x64.zip`
- CUDA 13：`llama-b<版本号>-bin-win-cuda-13.x-x64.zip`

文件名中的 build 号和 CUDA 小版本会随发布变化，请以 Releases 页面为准。如果同一项另列有匹配的 `cudart-llama-bin-win-cuda-*.zip`（CUDA DLLs），也一并下载并解压到同一目录。最后在网页设置中填写该目录里的 `llama-server.exe` 路径。

## 输出与隐私

- SRT 导出到所选输出目录；仅日文模式会生成 `sample-a.ja.srt`。每次运行的 SRT、JSON 和可选质量报告还会整套保存在 `tmp/outputs/`，任务卡从这套结果打开或下载文件。
- `models/` 保存已下载模型；`tmp/web/` 保存任务状态，`tmp/jobs/` 保存可恢复的任务中间文件，`tmp/log/` 保存日志。
- `tmp/outputs/` 保存正式结果，不能当作普通缓存删除。目前不会自动回收这些结果；删除任务卡也会保留它们和已导出的 SRT。需要腾出空间时，先备份所需结果，关闭程序后再清理不再需要的代次目录。
- 成功任务会清理一次性临时文件，但保留模型与跨任务 ASR 缓存。同一目录开了多个窗口时，只有最后关闭的那个执行清理——否则会删掉另一个窗口正在转写的中间音频。清理进行中启动新窗口，会先等它清理完再开始（最多 20 秒），控制台会说明正在等待。
- API 翻译只发送字幕文本，不发送视频或音频。具体数据处理规则仍取决于你选择的 API 服务。
- 质量报告用于辅助人工复查，不保证每条识别或翻译都完全正确。

删除运行中的任务会先请求取消。取消是一次请求，不是立刻结束：任务会先显示“停止中”，等实际执行它的环节停下来才变成“已取消”，之后再次删除才会清理该任务的临时目录。

任务结束时会短暂显示“保存中”，磁盘确认成功才显示“完成”。“保存失败”可重试写入任务状态，“产物提交失败”可重试提交已保存的整套结果，“字幕导出失败”可重试导出 SRT；这些恢复操作不会重新识别或翻译，也不要求重新配置 API。已提交的结果仍可从任务卡下载；文件损坏时会明确报错，需要恢复文件后再试。

同一输出路径被新任务接管后，旧任务不能再覆盖它，但已经提交的旧结果仍可下载。取消请求若晚于整套结果的提交，也会保留这次已完成的结果。

本地后端的领取等待有期限：`LOCAL_BACKEND_WAIT_TIMEOUT_S` 默认 600 秒，必须是有限正数；超过后该任务报错停止等待，旧实例继续清理，不能重新接入。释放租约或重置设置时，调用者最多等 `LOCAL_BACKEND_CLOSE_WAIT_S`（默认 15 秒），然后由后台继续关闭；同一后端只执行一个关闭操作，重复请求不会新增清理线程。清理卡住不等于资源已释放，不会因此启动替代实例。若底层关闭操作始终不返回，需要根据诊断确认进程状态并人工处理，程序不会强行终止 Python 线程。

如果占用显卡的子进程没能停下来——ASR 子进程或本地翻译服务都算——任务列表上方会出现提示条，并暂停派发新的 GPU 任务、暂不加载新的本地模型，程序会自行按间隔重试清理；也可以手动点“重新检查”“重试清理”或查看诊断信息，诊断里逐条列出还没确认释放的资源。提示条出现期间启动本地翻译会直接报错并说明原因——那时显存尚未释放，再加载一个本地模型只会撞上显存不足。“重试清理”只重试这些已经卡住的资源，不会停掉正在运行的任务。使用本地翻译时，取消只中止本机发出的请求，llama-server 可能仍在生成，显存不一定立即释放，提示条会说明这一点；该提示只在服务器进程确认退出后才消失，别的请求成功不算数。被取消过的本地翻译服务会退出使用：正在用它的任务照常跑完，之后开始的**本地翻译**任务会等它退出再起一个新的，所以紧接着启动的本地翻译可能要多等一会儿；等待期间删除该任务会立即结束等待，使用 API 翻译的任务不受影响。

## 常见问题

### 程序窗口无法打开

在程序目录打开 PowerShell，运行：

```powershell
.\jav-trans.exe --doctor
```

需要保留启动日志时使用 `--keep-console`；需要重装运行环境时使用 `--reinstall`。

### 下载速度很慢

在网页控制台的“识别设置”中填写代理，或启动时传入代理：

```powershell
.\jav-trans.exe --proxy http://127.0.0.1:7890
```

### CUDA 或显存报错

先关闭其他占用显卡的程序并更新 NVIDIA 驱动。保持默认的 `ASR_BATCH_SIZE=auto`，程序会在 OOM 后自动降低批大小；当前没有更小的 ASR 模型可切换。

### API 翻译失败

确认 API Key、Base URL 和模型名属于同一服务。OpenRouter 的模型名通常形如 `deepseek/deepseek-v4-flash`；DeepSeek 官方地址 `https://api.deepseek.com` 使用 `deepseek-v4-flash`。其他兼容服务请使用其文档给出的地址和模型名。

如果报错指向 `/responses` 路径不存在（404 或 `Not Found`），说明该服务只提供 Chat Completions 接口，无法使用；请改用支持 Responses 的服务，或改用本地翻译。

程序默认要求译文按 JSON Schema 返回（DeepSeek 官方地址除外，它只支持较宽松的 `json_object`）。如果服务商不支持严格 schema，返回结构错误或直接报错，可在 `.env` 中改用宽松约束：

```env
LLM_STRUCTURED_OUTPUT=json_object
```

反过来，如果希望 OpenRouter 只把请求发给能真正强制执行 schema 的供应商，可以设 `LLM_STRUCTURED_OUTPUT=json_schema`；此时未声明 `structured_outputs` 的模型会返回 404。

### 设置写错了会怎样

通用数字和开关设置留空时使用默认值；无法解析时也使用默认值，并警告字段名。数字超出范围时，上限类设置按边界处理，速率类设置回到默认值；`inf`、`nan` 不接受，整数设置也不能填写 `4.5` 这样的值。

启动时会检查常用设置，并集中列出已读取字段的问题，例如 `[WARN] 配置项 SUBTITLE_LINGER_S='-1'：低于允许的最小值 0，已按该边界处理`。仅在任务中读取的设置，会在首次读取时警告。改回合法值后重新读取即可清除对应警告。

有明确取值合同的设置仍会拒绝错误值，例如版本戳 `SUBTITLE_LAYOUT_ENGINE`、`SUBTITLE_TIMING_MODEL`，以及切块模式 `ASR_CHUNK_PAUSE_READING`。按报错中的字段名和允许值修改后再运行。

### 如何反馈长任务问题

日志位于 `tmp/log/<job_id>/`。反馈时请附上 `.run.log`、对应 SRT 和质量报告，并先移除 API Key、视频路径等隐私信息。

## 从源码运行

源码运行还需要 Git、uv、符合 `pyproject.toml` 约束的 Python，以及 FFmpeg Shared。TorchCodec 依赖 FFmpeg 共享 DLL；Windows 上应确保 Shared 版位于 `PATH`，且不要让静态版排在它前面。

```powershell
winget install --id Gyan.FFmpeg.Shared --exact

git clone https://github.com/jaykwok/jav-trans.git
cd jav-trans

uv venv
uv sync

$env:PYTHONIOENCODING="utf-8"
uv run --no-sync python launcher.py
```

浏览器默认打开 `http://127.0.0.1:2233`。端口被占用时会自动选择下一个可用端口，并在启动日志中显示实际地址。请使用 `uv` 安装项目依赖，不要用 `pip install` 逐个安装，以免误装 CPU 版 PyTorch。
