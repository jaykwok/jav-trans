# 进阶设置与排错

[返回使用说明](../README.md) · [启动与下载](#启动与下载) · [API 翻译](#api-翻译) · [本地翻译](#本地翻译) · [结果与恢复](#结果与恢复)

本文补充常用设置、任务恢复和源码运行方法。首次使用建议先按 [快速开始](../README.md#快速开始)，使用标准预设处理一个短视频。

## 启动与下载

### 程序窗口无法打开

在发布包所在目录打开 PowerShell，运行自检：

```powershell
.\jav-trans.exe --doctor
```

需要保留启动日志时使用 `--keep-console`；需要重装运行环境时使用 `--reinstall`。这些命令针对发布包；Git 源码工作副本使用文末的 `uv sync` 流程。

发布包已经包含 FFmpeg Shared。启动器优先使用已有 uv；找不到时会从 PyPI 下载到程序的 `bin/`，再准备 Python 和锁定的依赖。模型在首次运行对应任务时下载，不包含在轻量发布包里。

### 下载慢或连接失败

控制台中的代理入口为“网络代理”。填好地址和端口、打开开关后，可点击“测试连接”检查 HuggingFace 连通性。启动阶段也可以指定代理：

```powershell
.\jav-trans.exe --proxy http://127.0.0.1:7890
```

这里的端口仅为示例，请替换为本机代理实际监听的端口。HuggingFace 测试成功不代表 PyPI 或 API 服务也可访问；依赖安装、模型下载和翻译报错应分别检查对应服务。

首次安装会在控制台显示依赖下载进度；中断后重新启动即可继续准备。不要因为解压后的 ZIP 很小，就按 ZIP 大小估计安装所需空间。

## API 翻译

程序使用 Responses 协议，服务必须提供 `/responses`。仅支持 Chat Completions 的接口无法使用。

### 地址与模型要配套

| 服务 | Base URL 示例 | 模型名示例 |
| --- | --- | --- |
| OpenRouter（默认） | `https://openrouter.ai/api/v1` | `deepseek/deepseek-v4-flash` |
| DeepSeek 官方 | `https://api.deepseek.com` | `deepseek-v4-flash` |

以上是项目配置示例，具体可用模型以该服务当前返回的列表为准。换地址后，先保存 API Key 与 Base URL，再点“获取”重新选择模型并保存；不要直接沿用另一家服务的模型名。

如果 `/responses` 返回 404 或 `Not Found`，检查 Base URL、模型路由和服务是否支持 Responses。单个 404 不足以判断原因；只支持 Chat Completions 的服务需要更换。

### 结构化输出报错

程序默认要求译文按 JSON Schema 返回；DeepSeek 官方地址使用较宽松的 `json_object`。兼容服务不支持严格 schema 时，可在程序目录的 `.env` 设置：

```env
LLM_STRUCTURED_OUTPUT=json_object
```

如果希望 OpenRouter 只把请求发给声明支持强制 schema 的供应商，可以设为 `LLM_STRUCTURED_OUTPUT=json_schema`。此时模型没有可用的 `structured_outputs` 路由也可能返回 404。

### 翻译与上下文

API 翻译可使用全片参考、角色参考和用户术语。本地翻译逐条处理已经确定的日语原文单元，结合邻近原文和当前句命中的术语；全片参考与角色参考仅用于 API。

翻译优先保留否定、条件、数量、施受关系和语气。相同日语在不同语境中可以有不同译法，普通短译文不会仅因长短比例异常而被扩写。中文只在同一条字幕内换行，不重新切分时间轴。

## 语义复核

API 语义复核默认关闭，与“生成质量报告”是两个独立设置。在程序目录的 `.env` 写入以下内容并重启后启用：

```env
TRANSLATION_SEMANTIC_REVIEW_ENABLED=1
TRANSLATION_SEMANTIC_REVIEW_MAX_IDS=80
```

首轮翻译和常规修复后，程序从候选字幕中选择最多 80 条进行语义检查。修改建议必须引用原文依据，通过程序校验，再经过第二次独立比较才会采纳；复核记录保留修改前后文本。

调整 `TRANSLATION_SEMANTIC_REVIEW_MAX_IDS` 可改变候选上限。开启会增加 API 用量和等待时间；这是候选复核，不是全片逐句重译。本地 Hy-MT2 不执行此流程，模型复核也不能代替人工检查。

## 本地翻译

在 PowerShell 安装 llama.cpp，然后在“翻译设置”选择本地后端：

```powershell
winget install -e --id ggml.llamacpp
```

已安装并能自动查找到的 `llama-server` 无需重复填写路径。手动下载时，在控制台填写 `llama-server.exe` 所在文件夹或 exe 路径。翻译模型固定为 `Hy-MT2-7B-Q4_K_M.gguf`，首次翻译自动下载约 4.6 GB。

### 手动选择 CUDA 版

NVIDIA 用户可从 [llama.cpp 官方 Releases](https://github.com/ggml-org/llama.cpp/releases) 下载 Windows x64 CUDA 版。先运行 `nvidia-smi` 检查驱动支持的 CUDA 版本，再按官方发布说明选择兼容的构建。

文件名中的 build 号和 CUDA 小版本会变化，不要照抄旧版本文件名。如果同一发行项另列了匹配的 CUDA DLL 压缩包，也一并下载并解压到同一目录，再配置其中的 `llama-server.exe`。

### 切换后端与等待关闭

任务运行中切换翻译后端或本地 server 路径，会停止受影响的任务并说明原因。保存新设置后重新运行，可复用仍然有效的缓存。

本地后端等待可用实例的默认期限为 600 秒，由 `LOCAL_BACKEND_WAIT_TIMEOUT_S` 设置，必须是有限正数。超过后该任务报错停止等待，旧实例继续清理。`LOCAL_BACKEND_CLOSE_WAIT_S` 默认 15 秒，超过后由后台继续关闭；重复请求不会重复启动清理操作。

清理卡住时，资源尚未确认释放，程序不会据此启动替代实例。先查看 GPU 提示条与诊断，再按下节处理。

## 显卡与取消

### CUDA 不可用或显存不足

正式 ASR、真实训练和批量评估要求 CUDA，不提供静默 CPU 回退。先检查 NVIDIA 驱动并关闭其他占用显卡的程序。当前 ASR 模型要求至少 6144 MiB 物理显存，推荐 8 GB 及以上。

保留默认 `ASR_BATCH_SIZE=auto`，程序可在 OOM 后降低批大小。当前没有更小的 ASR 模型可切换；批大小调低也不能解决驱动不可用或模型最低显存不满足的问题。

### “停止中”还没结束

取消首先发出停止请求，任务会显示“停止中”。实际执行环节退出并确认后才显示“已取消”，再次删除才清理该任务的临时目录。

本地翻译取消时，llama-server 可能仍在生成，显存不一定立即释放。被取消过的服务会退出使用：正在使用它的其他任务正常完成，后续本地翻译任务等待旧服务退出，再启动新实例；等待期间可以删除任务以结束等待。API 翻译不受本地翻译实例等待的影响。

### GPU 未释放提示条

ASR 子进程或本地翻译服务未能确认退出时，任务列表上方会显示提示，暂停新的 GPU 任务和本地模型加载。程序会间隔重试清理，也可点击“重新检查”“重试清理”或查看诊断。

“重试清理”只处理已卡住的资源，不会停止其他正常任务。提示条以资源确实退出为解除条件，别的请求成功不能代替退出确认。

如果提示持续存在，根据诊断确认残留进程的状态并人工处理；程序不会强行终止 Python 线程。不要仅因等待超时，就认为显卡资源已经释放。

## 结果与恢复

### 保存失败时怎么继续

正常结束时，任务先显示“保存中”，磁盘确认成功后才显示“完成”。

| 状态 | 对应操作 | 是否重新识别或翻译 |
| --- | --- | --- |
| 保存失败 | 点击“重试保存”，重写任务状态 | 否 |
| 产物提交失败 | 点击“重试提交”，提交已保存的整套结果 | 否 |
| 字幕导出失败 | 点击“重试导出”，把已保存字幕导出到目标位置 | 否 |

先排除磁盘空间、目录权限或文件占用问题，再重试。这些交付恢复操作不需要重新配置 API。已提交的结果仍可从任务卡下载；文件损坏时会明确报错，需要恢复文件后再试。

同一输出路径被新任务接管后，旧任务不能再覆盖它，但已提交的旧结果仍可下载。取消请求若晚于整套结果的提交，会保留这次已完成的结果。

### 目录用途与清理

| 位置 | 内容 |
| --- | --- |
| 选择的输出目录 | 导出的 SRT；留空时为视频同目录 |
| `tmp/outputs/` | 每次运行整套正式结果，包括 SRT、JSON 和可选质量报告 |
| `models/` | 已下载模型 |
| `tmp/web/` | 任务状态 |
| `tmp/jobs/` | 可恢复的任务中间文件 |
| `tmp/cache/` | 可复用的运行缓存 |
| `tmp/log/` | 日志 |

删除任务卡会保留正式结果和已导出的 SRT。`tmp/outputs/` 不会自动回收；腾出空间前，先备份所需结果，关闭程序，再清理不再需要的结果目录。

成功任务会清理一次性临时文件，保留模型和跨任务 ASR 缓存。同一目录打开多个窗口时，只有最后关闭的窗口执行退出清理，避免影响其他任务。清理中启动新窗口会先等待，最多 20 秒，控制台会显示说明。

## 配置校验

通用数字和开关设置留空时使用默认值；无法解析时也使用默认值，并警告字段名。数字越界时，上限类设置限制到边界，速率类设置恢复默认值。`inf`、`nan` 不接受；整数设置不能填写 `4.5` 这样的值。

启动时会集中列出已读取配置的问题，例如：

```text
[WARN] 配置项 SUBTITLE_LINGER_S='-1'：低于允许的最小值 0，已按该边界处理
```

仅在任务中读取的设置会在首次读取时警告，改回合法值后重新读取即可清除对应警告。

具有明确允许值的设置仍会拒绝错误值，例如 `SUBTITLE_LAYOUT_ENGINE`、`SUBTITLE_TIMING_MODEL`、`ASR_CHUNK_PAUSE_READING`。按报错列出的字段名和允许值修改后再运行。

## 从源码运行

源码运行需要 Git、uv、符合 `pyproject.toml` 约束的 Python，以及 FFmpeg Shared。Windows 上确保 Shared 版位于 `PATH`，且不要让静态版排在它前面；TorchCodec 需要共享 DLL。

```powershell
winget install --id Gyan.FFmpeg.Shared --exact

git clone https://github.com/jaykwok/jav-trans.git
cd jav-trans

$env:PYTHONIOENCODING = "utf-8"
uv venv
uv sync
uv run --no-sync python launcher.py
```

浏览器默认打开 `http://127.0.0.1:2233`。端口被占用时会自动选择下一个可用端口，启动日志会显示实际地址。

使用 uv 按项目锁定配置安装依赖，不要通过全局 Python 或逐个 `pip install` 拼装环境，以免误装 CPU 版 PyTorch。源码工作副本的发布启动器自检只报告环境状态，正常依赖同步使用 `uv sync`。

## 反馈问题

日志位于 `tmp/log/<job_id>/`。反馈时说明所选模式、操作步骤和报错；需要附日志时，可提供 `.run.log` 与能复现问题的最小字幕片段、质量报告。

发送前移除 API Key、用户目录、视频路径、真实片名及其他个人信息。示例文件名使用 `sample-a`，截图中的敏感内容也需要处理。不要直接公开整个 `.env`、原始媒体或完整本地日志目录。
