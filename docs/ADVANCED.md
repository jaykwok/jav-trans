## 启动与下载

### 程序窗口打不开

在程序目录打开 PowerShell，运行自检：

```powershell
.\jav-trans.exe --doctor
```

自检会逐项检查程序文件、FFmpeg 和依赖（包括实际导入 PyTorch 等库），缺少依赖时当场补装，然后继续启动。提示“程序文件不完整”时，缺的是压缩包里的文件，无法自动补回：把同一版本的压缩包按[升级步骤](../README.md#升级到新版本)重新复制一次即可。

其他启动参数：

| 参数 | 作用 |
| --- | --- |
| `--keep-console` | 程序窗口打开后保留命令行窗口，便于查看启动日志 |
| `--proxy <地址>` | 使用指定代理，不再询问 |
| `--yes` | 自检和安装过程中不等待确认 |
| `--reinstall` | 重新安装运行环境 |
| `--install-only` | 只安装或自检，不启动程序 |

这些参数针对发布包；从源码运行见[从源码运行](#从源码运行)。

发布包已包含 FFmpeg Shared。启动器优先使用本机已有的 uv，找不到时从 PyPI 下载到程序目录的 `bin/`，再准备 Python 和锁定版本的依赖。模型不在发布包内，首次运行对应任务时下载。

### 下载慢或连接失败

首次安装前，启动器会实测下载速度并询问是否使用代理。安装完成后，也可以在控制台的“网络代理”中填写地址和端口并打开开关，再点“测试连接”检查能否访问 HuggingFace。启动时同样可以直接指定代理：

```powershell
.\jav-trans.exe --proxy http://127.0.0.1:7890
```

端口仅为示例，请换成本机代理实际监听的端口。HuggingFace 测试成功不代表 PyPI 或 API 服务也能访问；依赖安装、模型下载和翻译报错需要分别检查对应的服务。

安装时命令行窗口会显示依赖下载进度，中断后重新启动即可继续。发布包本身只有约 100 MB，但装好运行环境和模型后至少需要 17 GB，请按后者预留磁盘空间。

## API 翻译

程序使用 Responses 协议，服务必须提供 `/responses`；只支持 Chat Completions 的接口无法使用。

### 地址与模型要配套

| 服务 | Base URL 示例 | 模型名示例 |
| --- | --- | --- |
| OpenRouter（默认） | `https://openrouter.ai/api/v1` | `deepseek/deepseek-v4-flash` |
| DeepSeek 官方 | `https://api.deepseek.com` | `deepseek-v4-flash` |

表中仅为示例，可用模型以服务当前返回的列表为准。更换服务后，先保存 API Key 与 Base URL，再点“获取”重新选择模型并保存；不要沿用另一家服务的模型名。

`/responses` 返回 404 或 `Not Found` 时，依次检查 Base URL、模型路由，以及服务是否支持 Responses；仅凭一次 404 无法判断是哪一项出了问题。确认服务只支持 Chat Completions 时，需要更换服务。

### 结构化输出报错

程序默认要求译文按 JSON Schema 返回；DeepSeek 官方地址改用较宽松的 `json_object`。兼容服务不支持严格 schema 时，在程序目录的 `.env` 中设置：

```env
LLM_STRUCTURED_OUTPUT=json_object
```

如果希望 OpenRouter 只把请求发给声明支持强制 schema 的供应商，设为 `LLM_STRUCTURED_OUTPUT=json_schema`。这时若模型没有可用的 `structured_outputs` 路由，请求同样会返回 404。

### 翻译与上下文

API 翻译可以使用全片参考、角色参考和用户术语。本地翻译逐条处理已确定的日语原文单元，参考邻近原文和当前句命中的术语；全片参考与角色参考只用于 API。

翻译优先保留否定、条件、数量、施受关系和语气。同一句日语在不同语境中可以有不同译法；正常的短译文不会因为长度比例异常而被扩写。中文只在同一条字幕内换行，不会重新切分时间轴。

## 语义复核

API 语义复核默认关闭，与“生成质量报告”是两个独立设置。在程序目录的 `.env` 中写入以下内容并重启程序后启用：

```env
TRANSLATION_SEMANTIC_REVIEW_ENABLED=1
TRANSLATION_SEMANTIC_REVIEW_MAX_IDS=80
```

首轮翻译和常规修复完成后，程序从候选字幕中最多挑选 80 条做语义检查。修改建议必须引用原文依据、通过程序校验，并经过第二次独立比较后才会采纳；复核记录会保留修改前后的文本。

`TRANSLATION_SEMANTIC_REVIEW_MAX_IDS` 控制候选条数上限。开启后会增加 API 用量和等待时间。它只复核候选字幕，不是全片逐句重译；本地 Hy-MT2 不执行这一流程，模型复核也不能代替人工检查。

## 本地翻译

在 PowerShell 中安装 llama.cpp，然后在“翻译设置”中选择本地后端：

```powershell
winget install -e --id ggml.llamacpp
```

winget 安装的是 Vulkan 版，装好后 `llama-server` 位于 `PATH` 上，程序会自动找到，无需填写路径。手动下载的版本需要在控制台填写 `llama-server.exe` 所在文件夹或 exe 路径。

翻译模型固定为 `HY-MT2-7B-Q6_K.gguf`，首次翻译时自动下载，约 6.2 GB。服务器使用 q8_0 KV 缓存和 4 个并行槽，加载后约占 6.2 GB 专用显存。

翻译为中文时，程序会检查译文中是否残留全角或半角假名；检查不通过时，用禁止输出假名的语法重试。中点、长音符等单独出现的符号不算漏译。这项检查只约束字符，不能保证语义准确，短句和孤立发声仍需复查；靠这种重试才通过的条目会列在质量报告的“建议复查的译文”中。

### 手动安装 CUDA 版

在 NVIDIA 显卡上，CUDA 版比 Vulkan 版更快。可以从 [llama.cpp 官方 Releases](https://github.com/ggml-org/llama.cpp/releases) 下载 Windows x64 CUDA 版：先运行 `nvidia-smi` 查看驱动支持的 CUDA 版本，再按官方发布说明选择兼容的构建。

文件名中的 build 号和 CUDA 小版本会随发布变化，请以当前 Releases 页面为准。如果同一发行版另外提供了配套的 CUDA DLL 压缩包，也一并下载并解压到同一目录，然后在控制台填写其中的 `llama-server.exe`。

### 切换后端与等待关闭

任务运行中切换翻译后端或本地 server 路径，会停止受影响的任务并说明原因。保存新设置后重新运行，可复用仍然有效的缓存。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| `LOCAL_BACKEND_WAIT_TIMEOUT_S` | 600 秒 | 任务等待可用本地实例的上限；超时后该任务报错并停止等待，旧实例继续清理 |
| `LOCAL_BACKEND_CLOSE_WAIT_S` | 15 秒 | 关闭实例时的等待时间；超时后转到后台继续关闭，重复请求不会重复发起清理 |

两项都必须是有限正数。

清理卡住时，资源尚未确认释放，程序不会另启新实例来替代。先查看 GPU 提示条与诊断信息，再按下一节处理。

## 显卡与取消

### CUDA 不可用或显存不足

语音识别必须使用 CUDA，不会悄悄改用 CPU。先检查 NVIDIA 驱动，并关闭其他占用显卡的程序。程序最低要求 8 GB 物理显存。

请保留默认的 `ASR_BATCH_SIZE=auto`，程序会在显存不足（OOM）后自动降低批大小。目前没有更小的识别模型可换；调低批大小也解决不了驱动不可用或显存低于最低要求的问题。

### “停止中”一直不结束

点击取消后，任务先显示“停止中”；正在执行的环节确认退出后，才会变为“已取消”。之后删除任务，才会清理它的临时目录。

取消本地翻译时，llama-server 可能还在生成，显存不一定立即释放。被取消过的服务实例不再接收新任务：正在使用它的其他任务会正常完成，之后的本地翻译任务会等旧实例退出后再启动新实例；等待期间可以删除任务来结束等待。API 翻译不受影响。

### GPU 未释放提示条

识别子进程或本地翻译服务未能确认退出时，任务列表上方会出现提示条，并暂停新的 GPU 任务和本地模型加载。程序会定时重试清理，你也可以点“重新检查”“重试清理”或查看诊断。

“重试清理”只处理已经卡住的资源，不会停止其他正常运行的任务。提示条只在资源确认退出后才会消失，其他请求成功不能代替退出确认。

如果提示条一直存在，请根据诊断确认残留进程的状态并手动处理；程序不会强行终止 Python 线程。等待超时不代表显卡资源已经释放。

## 结果与恢复

### 保存失败后怎么继续

任务正常结束时先显示“保存中”，结果确认写入磁盘后才显示“完成”。

| 状态 | 操作 | 是否重新识别或翻译 |
| --- | --- | --- |
| 保存失败 | 点击“重试保存”，重新写入任务状态 | 否 |
| 产物提交失败 | 点击“重试提交”，提交已保存的整套结果 | 否 |
| 字幕导出失败 | 点击“重试导出”，把已保存的字幕导出到目标位置 | 否 |

重试前先排除磁盘空间不足、目录无写入权限或文件被占用等问题。这些重试不需要重新配置 API。已提交的结果仍可从任务卡下载；文件损坏时会明确报错，需要先恢复文件再重试。

同一输出路径被新任务接管后，旧任务不能再覆盖它，但旧任务已提交的结果仍可下载。如果取消请求晚于整套结果提交，这次已完成的结果会保留。

### 目录用途与清理

| 位置 | 内容 |
| --- | --- |
| 所选输出目录 | 导出的 SRT；留空时为视频所在目录 |
| `.env` | 已保存的设置 |
| `models/` | 已下载的模型 |
| `tmp/outputs/` | 每次运行的整套正式结果，包括 SRT、JSON 和可选的质量报告 |
| `tmp/web/` | 任务状态 |
| `tmp/jobs/` | 可恢复任务的中间文件 |
| `tmp/cache/` | 可复用的运行缓存 |
| `tmp/log/` | 日志 |

删除任务卡会保留正式结果和已导出的 SRT。`tmp/outputs/` 不会自动清理；需要腾出空间时，先备份所需结果并关闭程序，再删除不需要的结果目录。

任务成功后会清理一次性临时文件，保留模型和跨任务复用的识别缓存。同一程序目录打开多个窗口时，只有最后关闭的窗口执行退出清理，以免影响其他任务；清理期间启动新窗口会先等待，最多 20 秒，并在命令行窗口中说明原因。

## 配置校验

一般的数字和开关设置留空时使用默认值；无法解析时也使用默认值，并提示字段名。数字越界时，上限类设置限制到边界，速率类设置恢复默认值。不接受 `inf`、`nan`；整数设置不能填写 `4.5` 这类小数。

启动时会集中列出已读取配置的问题，例如：

```text
[WARN] 配置项 SUBTITLE_LINGER_S='-1'：低于允许的最小值 0，已按该边界处理
```

只在任务中读取的设置会在首次读取时提示；改回合法值后，下次读取时提示即消失。

只接受固定取值的设置填错时会直接报错，例如 `SUBTITLE_LAYOUT_ENGINE`、`SUBTITLE_TIMING_MODEL`、`ASR_CHUNK_PAUSE_READING`。按报错中的字段名和允许值修改后再运行。

## 从源码运行

从源码运行需要 Git、uv、满足 `pyproject.toml` 版本约束的 Python，以及 FFmpeg Shared。Windows 上要确保 Shared 版在 `PATH` 中，且静态版不能排在它前面：TorchCodec 需要加载 FFmpeg 的共享 DLL。

```powershell
winget install --id Gyan.FFmpeg.Shared --exact

git clone https://github.com/jaykwok/jav-trans.git
cd jav-trans

$env:PYTHONIOENCODING = "utf-8"
uv venv
uv sync
uv run --no-sync python launcher.py
```

浏览器默认打开 `http://127.0.0.1:2233`。端口被占用时会自动改用下一个可用端口，实际地址见启动日志。

请用 uv 按项目锁定配置安装依赖，不要用全局 Python 或逐个 `pip install` 拼装环境，以免装成 CPU 版 PyTorch。在 git 工作副本中，发布启动器的自检只报告环境状态、不会改动 `.venv`；同步依赖请直接使用 `uv sync`。

## 反馈问题

请在 [GitHub Issues](https://github.com/jaykwok/jav-trans/issues) 反馈，说明所用模式、操作步骤和报错信息。日志位于 `tmp/log/<job_id>/`；需要附日志时，提供 `.run.log`，以及能复现问题的最小字幕片段或质量报告。

发送前请删除 API Key、用户目录、视频路径、真实片名等个人信息，示例文件名用 `sample-a` 代替；截图中的敏感内容也要打码。不要直接公开整个 `.env`、原始媒体或完整的本地日志目录。
